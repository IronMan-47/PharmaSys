PharmaSys: Technical Workflow & Architecture

This document delineates the data flow models and architectural pipelines for the PharmaSys application modules, mapping the communication layers between the frontend, backend APIs, and the database cluster.

2. Global System Workflows

A. Authentication & Security Flow (AuthContext)

  1. Login Attempt: Client submits credentials via Login.jsx. React executes an axios.post to /api/auth/login.
  2. Backend Verification: The Express router queries the users collection in MongoDB. Upon credential verification, the backend signs a JSON Web Token (JWT) and transmits it to the client.
  3. State Preservation: The React client receives the JWT and persists it into the browser's localStorage.
  4. Global Context: The AuthContext.jsx provider wraps the application tree. It validates the presence of the token in localStorage. If validated, it mutates isAuthenticated to true, unblocking the Protected Routes.
  5. Secure API Calls: For all subsequent HTTP requests, the client attaches the JWT to the Authorization header payload.

B. Full-Stack Data Pipeline

  1. Frontend (Axios): All HTTP requests utilize the axios client. Base endpoints are dynamically injected via ${import.meta.env.VITE_API_URL} to ensure environment portability.
  2. Backend (Express Middleware): Within server.js, global middleware intercepts requests, parses JSON bodies via express.json(), and injects the active MongoDB connection pool into the req.db object.
  3. Database (MongoDB Native Driver): To maximize query execution speed, the architecture bypasses Object-Relational Mappers (ORMs) in favor of the Native MongoDB driver (e.g., executing await req.db.collection('medicines').insertOne(data) directly).

3. Module Logic & Data Flow

Module 1: POS Dashboard Checkout Flow

  1. Data Hydration: Upon component mount, useEffect executes a GET request to /api/medicines to populate the inventory grid, applying a client-side filter (stock < 10) for low-stock flagging.
  2. Cart State Aggregation: Selecting an item invokes addToCart, checking for _id collisions in the state array. Duplicates trigger a .map() quantity increment; unique items trigger a state spread insertion.
  3. PDF Rendering: Executing "Complete Purchase" invokes jsPDF, parsing the local cart array into a tabular format and generating a client-side PDF blob for download.
  4. Transaction Persistence: Concurrently, an axios.post payload containing the cart array and demographic zip code is sent to /api/transactions, triggering an .insertOne() operation in MongoDB.

Module 2: Inventory CRUD & Search Flow

  1. Instant Search Filtering: State mutations to searchTerm trigger immediate client-side array filtering via .filter() and .includes(), bypassing database query latency.
  2. Create (Stock In): Form submission POSTs data to /api/medicines. The Express router extracts warehouse metadata (Shelf/Box), appends an ISO timestamp, and commits the document to the database.
  3. Destroy (Delete): Invoking deletion sends a DELETE request to /api/medicines/:id. The backend parses the string into an ObjectId and executes .deleteOne().

Module 3: Sales History Flow

  1. Data Fetching: Component initialization GETs /api/transactions.
  2. Resilient Rendering: The UI tier enforces strict type-checking (Array.isArray(transactions)) prior to DOM mapping, preventing fatal application crashes against malformed API responses.
  3. Revenue Aggregation: Total historical revenue is computed dynamically via the .reduce() prototype function rather than iterative loops.

Module 4: System Audit Logs

  1. Passive Logging Pipeline: Inventory additions trigger a secondary backend sequence, automatically writing an audit document to the logs collection.
  2. Chronological Display: The Logs component queries /api/logs. The backend executes a sort cursor (createdAt: -1) to ensure strict descending chronological display of administrative actions.
