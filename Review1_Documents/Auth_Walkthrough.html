PharmaSys: Authentication System Guide

This guide documents the Admin Authentication system implementation within the PharmaSys architecture.

1. System Overview

The authentication flow addresses two primary access control constraints:

  1. Identity Verification: Processing credentials via the Login Form.
  2. Route Protection: Validating authorization state prior to rendering secured components.

This is achieved via a Client-Server verification model. The React Frontend communicates with the Express Backend to verify administrative credentials. Upon successful validation, the backend issues a JWT (JSON Web Token) to maintain the session state.

2. Backend Authentication API (backend/routes/auth.js)

The backend route processes the authentication payload.

router.post('/login', (req, res) => {
  const { username, password } = req.body;

  if (username === 'admin1' && password === '12345678') {
    const token = jwt.sign({ username }, 'secret_key', { expiresIn: '24h' });
    return res.json({ success: true, token });
  }

  return res.status(401).json({ success: false, error: 'Invalid credentials' });
});

Implementation Details: The username and password are extracted from the request body. If the credentials match the database requirements, the jsonwebtoken library signs a secure token valid for 24 hours. Invalid attempts yield a 401 Unauthorized HTTP response.

3. Frontend Global State (frontend/src/context/AuthContext.jsx)

To propagate the authentication state across the application tree, the system leverages React's Context API.

  • token state: The JWT is stored persistently in the browser's localStorage to maintain session viability across page reloads.
  • login function: Executes an Axios POST request to the backend and persists the resulting token.
  • logout function: Clears the token from localStorage and resets the application state.

4. Protected Routes (App.jsx)

Critical interfaces such as the Dashboard and Inventory are secured using a higher-order component.

function ProtectedRoute({ children }) {
  const { token } = useContext(AuthContext);
  
  if (!token) {
    return <Navigate to="/login" replace />;
  }
  
  return children;
}

In the primary router configuration, layouts are nested within this protection layer:

<Route path="/*" element={
  <ProtectedRoute>
    <MainLayout />
  </ProtectedRoute>
} />

Unauthorized direct URL access (e.g., navigating directly to /inventory) is intercepted by the ProtectedRoute, resulting in an immediate redirection to the authentication interface.

5. Summary

The system utilizes a fully functional, token-based authentication architecture:

  • The Node.js backend securely issues signed JWTs.
  • The React frontend stores tokens persistently via localStorage.
  • Application routes are strictly protected from unauthorized access via Context API state checks.
